# Production monthly investor reporting

The owner can create a month, describe what happened in ordinary Japanese, prepare an investor summary, attach financial PDFs, review, approve and publish. Investors receive a chronological archive with a concise monthly summary and downloadable P/L, B/S, trial balance, cash flow or other supporting documents. No missing financial number is presented as zero or inferred from prose.

## Runtime and access

The existing mock runs independently in development. Production uses Supabase Auth, PostgreSQL and a private Storage bucket. Production credentials never belong in development. Pages, actions and document/PDF routes use verified Auth users, current database memberships and RLS. Admin mutations require TOTP AAL2. Memberships are not sourced from editable user metadata. A trusted email invitation becomes an access grant only after Supabase verifies that email. Access revocation is checked on each request/download. The application does not need a service-role key.

Use a dedicated IR project; actual provisioning waits for the owner's destination and initial admin email. Deploy only the reviewed code and tested migrations, without mock seed data. Existing unrelated Prorium services remain untouched. Auth redirect URLs and email delivery must be configured for the final domain.

## Monthly updates

Create produces an empty draft, with no invented business results. Admin-only source notes are kept separately from investor content. A concise editable summary and key developments are prepared from those notes; a deterministic editorial mode can organize supplied text without an external model. Live AI is conditional on the separately authorized provider setup. The input cannot authorize publication. Changes to notes/output reset approval. A version is published only after human review and approval of the exact summary, financial snapshot and document manifest. Revisions clone a new draft and preserve the old publication.

The text-only monthly report is valid. It clearly says that financial figures are not yet entered and links to the attached financial statements; it does not render zero KPIs or synthetic charts. Admin can independently enter validated actual KPIs and prior-year baselines. Forecast information stays separate.

## Documents

PDF categories: P/L, B/S, trial balance, cash flow, other. Admin supplies title, target month, statement basis, PDF and notes. Limit 4 MiB per file (compatible with the initial serverless upload path); verify PDF signature, MIME, size and SHA-256. The object key is generated by the server. Reserve metadata → authenticated private upload → atomic attachment to draft. Pending or failed uploads never become visible. Attaching/removing a file invalidates approval. Published manifests and objects cannot be replaced. A revision can reuse immutable documents.

Investor downloads are authorized application endpoints, never public object URLs. PDF responses are attachments with private/no-store and a sandbox policy. The investor can only download ready documents included in a published version of their granted company. A separate documents library groups by month/category.

## PDF and deployment

The investor report still exports as PDF. Production uses a bundled serverless Chromium and the configured HTTPS application origin; it forwards the authenticated cookies only to that origin and blocks other destinations. Local mock export retains system Chromium and loopback. Add a nonce CSP for production scripts, private response caching and dynamic authenticated pages.
