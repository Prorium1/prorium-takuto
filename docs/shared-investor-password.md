# Shared initial investor password

Status: implemented and reviewed, but not enabled in production. Automatic approval review rejected creating the common Production Secret because the cross-account effect of sharing a weak password across future investor accounts requires explicit acknowledgement. Do not deploy the changed Edge Function or retry the secret write until that concern is resolved. No production password or authentication setting was changed.

The owner requested the same six-character initial password for all registered investors. Store its value only in the Production-scoped `INVESTOR_INITIAL_PASSWORD` Vercel Secret. Do not commit it, add it to Preview/Development, or pass it in a page prop. The initial rollout found zero active and zero inactive investor invitations, so no existing investor account needs a password reset.

The admin registration action reads this server setting after verifying the administrator and passes it to the existing credential Edge Function. Only an authenticated administrator for the company can supply a password. The existing SQL reservation still protects administrators, unrelated users, foreign companies, changed email identities and disabled invitations. All password changes use the supported Supabase Auth Admin API; password strength policy errors fail with a generic, actionable message. No Auth schema or RLS changes are needed.

The result is shown to the issuing administrator for copying into an invitation, as before. Registration uses the common initial password; an acknowledged reset returns an eligible investor to the configured initial password. Since a reset can reapply the same value, the UI no longer claims that it always invalidates a previous password. An absent setting retains individually generated passwords. Mock previews show the shared-password flow using the existing synthetic demo credential only.

A shared password does not distinguish one investor from another: anyone who knows it and another active investor email can sign in as that investor. This is the owner's explicitly requested access model. It does not grant administrator privileges, remove the invitation requirement, or expose unpublished reports. Email-link, Google and platform login remain unchanged. Changing the configuration later does not retroactively reset existing accounts; use the admin reset action for those accounts.

Verification covers identical supplied passwords on create/reset, refusal before mutations for invalid inputs, rejected investor/cross-company callers even when supplying a password, production-only configuration, generated-password fallback, the existing SQL protection matrix, and the copy/dismiss interface with synthetic data. No real accounts are created or logged into for testing, and no invitations are sent.

`npm run check` passed (87 domain/SQL tests, 22 render tests, typecheck, lint and baseline checks). The 9 relevant Playwright login/report tests and the optimized Next.js Mock build passed. Independent review reported no actionable findings and separately passed the 10 focused password/core/SQL tests. Live Auth behavior and the requested Production Secret remain unverified because activation is pending approval.
